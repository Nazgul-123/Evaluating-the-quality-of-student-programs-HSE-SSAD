# Лабораторная работа: Формулирование требований к программной системе

## Цель работы
Научиться анализировать поставленную задачу, формулировать функциональные и нефункциональные требования к проектируемой системе.

## Ожидаемые результаты

### Перечень заинтересованных лиц (стейкхолдеров) (2 балла)
- **Преподаватели и ассистенты**: 5 человек, ответственные за оценку студенческих работ, предоставление обратной связи, управление системой и добавление/изменение данных.
- **Студенты специальности РИС**: 400 человек, пользователи системы, которые будут загружать свой код и получать оценки и комментарии.
- **Администратор системы**: 1 человек, ответственный за управление правами доступа, настройку системы и внесение изменений в базу данных.

### Перечень функциональных требований (2 балла)
1. **Автоматическая проверка исходного кода студентов по выделенным критериям**:
   - Оценка корректности решения задачи.
   - Анализ стиля и качества написанного кода.
   - Проверка полноты тестирования.
   - Проверка соответствия стандартам программирования.
   ...(будет дополняться)
   
2. **Генерация подробного отчета с комментариями для преподавателя (и, возможно, студента)**:
   - Определение класса оцененного кода студента (плохой, средний, отличный).
   - Краткий комментарий по каждому критерию по работе студента.

3. **Интеграция с Telegram (создание чат-бота)**:
   - Простой и интуитивный интерфейс для взаимодействия с системой.
   - Возможность выбора лабораторной работы.
   - Выбор режима отображения оценок: по всем работам, по группам, по конкретному студенту.
   - Формирование отчёта по работе студента.

4. **Интеграция с GitHub** и автоматическая выгрузка программ студентов по запросу преподавателя (и, возможно, студента).

### Перечень сделанных предположений (2 балла)
- Предполагается, что студенты имеют базовые навыки работы с GitHub.
- Ожидается наличие стабильного интернет-соединения для работы системы.
- Преподаватели готовы использовать систему для оценки работ студентов.
- Студенты будут активно использовать систему для улучшения своих навыков программирования.
- Система будет доступна через чат-бот в Telegram.
- Использованная модель для генерации отчета и классификации кода останется доступной.
- GitHub и Telegram останутся доступными.
- Модель не будет переобучена и недообучена.

### Перечень нефункциональных требований (2 балла)
1. **Производительность**:
   - Система должна обеспечивать высокую производительность при обработке большого количества запросов, включая до 400 студентов одновременно.

2. **Безопасность данных**:
   - Уровень безопасности данных студентов и преподавателей должен быть высоким, включая защиту личной информации и результатов интеллектуальной деятельности студентов.

3. **Масштабируемость**:
   - Необходимо реализовать архитектуру, которая позволит системе масштабироваться, чтобы при увеличении количества студентов время обработки запросов увеличивалось лишь на приемлемое значение.
   - Необходимо выбрать модель, которая позволит обрабатывать запросы и генерировать ответы для большого количества работ студентов за приемлемое время (не позднее 30минут).

4. **Интерфейс пользователя**:
   - Интерфейс системы должен быть интуитивно понятным и удобным для пользователей, обеспечивая легкий доступ ко всем функциям через чат-бота в Telegram.
   - Визуальные элементы интерфейса должны быть четкими и понятными, с логичной навигацией между различными функциями.

5. **Доступность**:
   - Система должна быть доступна 24/7, обеспечивая непрерывный доступ преподавателей к функционалу без простоев.

6. **Устойчивость к сбоям**:
   - Система должна продолжать генерировать отчет, который не закончила генерировать, при возникшем сбое, обеспечивая сохранение прогресса и возможность завершения процесса после восстановления работы системы.
