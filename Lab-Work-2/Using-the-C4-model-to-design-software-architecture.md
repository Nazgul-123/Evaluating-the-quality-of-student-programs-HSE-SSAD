### 2. Диаграмма контейнеров
![C4-container](https://github.com/user-attachments/assets/213926c9-f96d-4535-a265-3c8d4a8ab0e2)

**Контейнеры системы:**
1. Чат-бот (Telegram Bot):
  - Основной интерфейс для взаимодействия преподавателей и студентов с системой.
  - Обрабатывает запросы пользователей, отправляет их на сервер и получает ответы.

2. Сервер приложения:
  - Обрабатывает бизнес-логику.
  - Взаимодействует с моделью машинного обучения для анализа и классификации кода.
  - Генерирует отчеты и комментарии по каждому критерию оценки.
  - Обеспечивает интеграцию для автоматической выгрузки кода по запросу преподавателя.

3. База данных:
  - Хранит информацию о преподавателях (ID телеграм пользователя, корпоративная почта).

4. Система контроля версий (GitHub):
  - Хранит исходный код студентов.
  
#### **Архитектурный стиль:** Сервисная архитектура

**Обоснование выбора:**

1. **Улучшенная безопасность**: 
   Серверная архитектура позволяет централизовать управление данными и логикой приложения, что облегчает контроль доступа и защиту от несанкционированного доступа.

2. **Масштабируемость**: 
   Серверы легко масштабируются для обработки растущего количества запросов, что обеспечивает высокую производительность приложения.

3. **Удобство обновления и обслуживания**: 
   Обновление и обслуживание приложения, реализованного на серверной архитектуре, проще и быстрее, так как изменения необходимо внести только на сервере, а не на каждом клиентском устройстве.

4. **Доступность**: 
   Серверная архитектура обеспечивает доступность приложения с различных устройств, включая компьютеры, смартфоны и планшеты.

5. **Повышенная функциональность**: 
   Серверная архитектура позволяет реализовать более сложные и функциональные приложения, используя преимущества языков программирования на стороне сервера.

6. **Интеграция с другими системами**: 
   Серверная архитектура упрощает интеграцию приложения с другими системами и сервисами, такими как базы данных и API.



### 3. Диаграмма компонентов
![C4-Компоненты(Система оценки кода)](https://github.com/user-attachments/assets/3432a964-5314-4f67-a35b-6b63a9e8b8c4)

▎**Компоненты системы**
1. **Telegram-бот**
   - Интерфейс для преподавателей: Позволяет авторизованным преподавателям запрашивать отчеты по коду студентов и получать результаты в текстовом формате.
   - Интерфейс для студентов: Позволяет студентам загружать свои работы и получать отчеты с комментариями по критериям.

2. **Система оценки кода**
   - Модель для анализа кода: Выполняет автоматическую проверку загруженного кода на основе заданных критериев. Формирует краткие комментарии по каждому критерию.
   - Модель для классификации кода: Классифицирует код на "плохой", "средний", "отличный".
   - Модуль генерации отчетов: Собирает результаты анализа, класс кода и комментарии в текстовый документ, который отправляется преподавателю или студенту.

3. **База данных**
   - Хранение данных о преподавателях: Содержит информацию о преподавателях, включая ID Telegram пользователя и корпоративную почту.

4. **Система контроля версий (GitHub)**
   - Хранит исходный код студентов.
   - Обеспечивает интеграцию для автоматической выгрузки кода по запросу преподавателя.

▎**Взаимодействие компонентов**
- Telegram-бот взаимодействует с системой оценки кода, получая запросы на анализ кода от студентов и преподавателей.
- Модель для анализа кода обрабатывает загруженный код, формирует комментарии на основе заранее заданных критериев для оценки кода и предоставляет результаты анализа модулю генерации отчетов для формирования итогового документа.
- Модель для классификации кода обрабатывает загруженный код, результаты анализа модели анализа кода, классифицирует код и предоставляет результаты модулю генерации отчетов для формирования итогового документа.
- База данных хранит информацию о преподавателях, необходимую для авторизации и отправки отчетов.
- GitHub по запросу через бот загружает код студентов для дальнейшего анализа с помощью моделей машинного обучения.
